# 单一 UI 任务与逻辑模块式 App

全局只有一个 FreeRTOS 任务承载 UI 与全部 App：App 是逻辑模块而不是任务，前台 App 持有事件循环权，后台 App 按各自的后台策略挂起或运行轻量逻辑。

这样定的理由：默认单任务把并发风险降到零、状态可推理，对以 UI 为中心的框架是决定性优势。代价是需要真并行（长阻塞 I/O、重后台计算）的 App 必须显式把后台策略声明为"拥有自己的任务"——把并行做成每个 App 的配置项，而不是框架结构的分叉。

## Considered Options

- **严格单任务**：任何 App 都不允许拥有任务。最简，但排除了长时间阻塞型的后台工作。
- **每个 App 一个任务、只有一个能画**：并行能力最强，但把并发与共享状态的风险摊给了所有 App。
