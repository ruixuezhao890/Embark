# 字体换装：SD 卡上的整份 TTF（先通后删）

决策见 `docs/adr/0017-font-ttf-from-sd.md`。本目录是它的落地拆分。

## 目标

界面与阅读器的所有文字，都由 SD 卡上的一份 TTF 在运行期栅格化得到；构建期不再生成、也不再拷贝任何字库文件。

## 边界（不在本 spec 内）

- 复杂文字 shaping（天城文等）、竖排直排：**明确不做**。
- 阿拉伯/希伯来 RTL：可选，需真机实测后再决定（`lv_txt_ap.c` 的映射表要求字体自带 Presentation Forms-B 码点）。
- 西里尔/希腊/泰文：推迟。没有单一字体同时覆盖 CJK 与泰文，要支持就得多个 face + fallback 链。
- 行首禁则与断行质量：见 issue 07，不阻塞换装。

## 两步走

1. **先通**（issue 01/02）：TTF 通道顶替全部 7 个字号槽，6 张屏零视觉回归，无卡仍能退回内置兜底。
2. **后删**（issue 03/04/05/06）：删 BIN 生成链与拷卡流程、退役旧记账实现、删 flash 分区与探针 mmap。

## 验收（整条赛道）

- 6 张 AiDoGUI 屏视觉零回归：`line_height` / `base_line` 与 BIN 一致，字重墨量差 ≤ 1%（ADR 0016 的判据口径）。
- 无卡启动：界面用 `embark_zh_14` 正常显示；阅读器显示"未插卡 / 字体未就绪"态，不崩、不撞 assert。
- 拔卡重插不崩（具体行为待定，见 ADR 0017「未做」）。
- 宿主与真机同一份代码路径，差异只在字体来源。
- CI：`font-audit` 改成 cmap 覆盖后，仍能抓到故意埋的缺字（`--selftest` 必须继续有效）。
